# The Three Registers

One planned element is recorded in up to three places, by different commands at different times. Each register is authoritative for its own column and for nothing else; nothing keeps them consistent unless a check does.

| Register | Lives in | Says | Written by | Checked by |
|---|---|---|---|---|
| `## Usage Tracker` | the canon file that owns the element | this element belongs in B1 Ch.07 | `/book setup`, `/book fix`; `/book chapter` Step 5.5 sets `planned` → `written` | `chapter-writer.md` 2.6.c, `coherence-check.md` K, `fidelity.md` class (d) |
| `**context:**` list | the chapter's header in `chapters/<book>/outline.md` | to write B1 Ch.07, load these files | the outline author; `/book chapter` 2.6.a and 2.6.c auto-add | `chapter-writer.md` 2.6.a/2.6.b, `coherence-check.md` K, R, S |
| §Inline Plant Tracking | one table in the book's outline header | this element recurs at #1 Ch.05, #2 Ch.12, #3 Ch.14, #4 Ch.19 | the outline author; `/book fix` on a Chekhov finding | `coherence-check.md` J, `chapter-writer.md` 2.6.c, `fidelity.md` class (e) |

**Reachability set — the rule binding tracker to context.** A chapter reaches a canon file if the file is in the always-loaded set, in the texture-palette proxy, in the chapter's `**context:**` list, **or** in the chapter's own level directory (`world/level-<N>-<this chapter's level>/`) carrying a `## Usage Tracker` row for this Book+Ch. A row whose owning file is outside all four routes for its target chapter can be neither rendered nor ticked.

The first two routes are declared in the outline header §Context Tags and parsed from it at run time, never hardcoded by a consumer. The fourth is a rule rather than a list: `chapter-writer.md` Step 1 lists the chapter's own level directory and opens exactly the files whose tracker rows name this Book+Ch, so those rows need no `context:` entry and 2.6.c does not auto-add them. Every other tracker row does need one — `world/` root files, `plot/` and `characters/` are reached by no rule, and a root file owning a recurring element is unreachable from every chapter that renders it until each one lists it.

The `**context:**` list is therefore authoritative for the chapter's conditional files, not a record of everything the chapter loads.

**Tools that compute reachability.** The skill ships one: `scripts/chapter_load.py`, a read-only derived view over the three registers. Do not reimplement it per project. It implements all four routes, and a three-route implementation reports level-directory rows as unreachable — in `ground-truth`, an early version reported 314 rows of which 226 were reachable through the fourth. Two independent passes then corroborated the inflated figure, because both asked whether the file was in the context list instead of whether the chapter reached it.

Run it from the project root, or set `BOOK_PROJECT_ROOT`; it resolves the root from the git top level otherwise, never from its own install path. `--check` is the pipeline guard and exits 1 on unassigned rows, orphans on drafted chapters, unreachable-MISSING rows, or malformed tracker rows; 2 on a `context:` entry naming no file, which is a defect in the outline rather than a parse detail to skip. The other modes list rather than judge: `--unreachable`, `--illegal-load`, `--free`, `--chapter B2:09`, `--unassigned`, `--orphans`, `--written`, `--book-form`, `--stale`, `--renumber`, `--devplan-drift`.

It reads the project off the tree and holds no list of its own: books from `chapters/book-*/`, drafted chapters from the prose on disk, level names and directories from `world/level-<n>-<name>/`, Level-0 chapters from the outlines' `**Level:**` fields. Every one of those was a hand-maintained constant first, and each stopped covering the corpus the day it changed while the guard kept reporting OK. A project that adds a level directory or a fourth book gets it with no code edit; a project whose layout differs from the one `init.md` scaffolds does not, and that is the tradeoff.

The consuming project keeps a `chapter-load.py` shim so pipeline scripts, hooks and tests can invoke a stable path. `tests/test_chapter_load.py` runs the model against a synthetic project and is what a freshly scaffolded project runs; a project's own suite is a regression record of defects measured in its corpus and stays there.

**Level register.** The chapter's `**Level:**` decides which level-scoped directories are legal for it, and outranks the other two registers: a barred file is reported, never auto-added, whatever a tracker row or a plant instance says. A row in a *different* level's directory is reachable by no route — the fix is to move the content or retarget the row, never to add a `context:` entry. → `chapter-writer.md` §Level register.

A chapter that genuinely crosses levels declares the second level in its own `**Level:**` field, and that declaration is the only thing that authorizes the crossing — never the context list, which is the thing being checked. A level named outside parentheses is co-primary (`Ark + Reality`): the chapter is equally at both and is a placement slot for either one's canon. A level named inside them is an incursion (`Ark (Reality residue)`, `Dome (Ark flash → Gate)`): it authorizes the load and opens no slot. The declaration counts in **both** directions — it exempts the chapter's context entries and it makes a tracker row in that level's directory legal — and honoring it in one direction only makes the two checks contradict each other about the same chapter.

**A directory is a load boundary; a section heading is not.** The register rule is enforceable because the chapter cannot open a file in another level's directory. A level-named section *inside* a level-neutral file is a topic label: the file is loaded whole, and the heading says what the content is about, not who can perceive it. Two guards are blind here by construction, and in `ground-truth` two Dome weather rows sat on an Ark chapter for that reason — the reachability check called them MISSING because the file's directory is neutral, so the obvious repair would have added the file to the Ark chapter's context list and made a Dome percept loadable inside an Ark POV.

The placement rule that follows: **when an element is a percept only one level can have, its row belongs in that level's directory**, not in a level-named section of a neutral file. That converts the dangerous cases into ones the register check already catches, which is why no checker reads headings as registers. Measured in `ground-truth` on 2026-07-27: 173 level-named sections in neutral files hold 73 rows whose target chapter is at another level, and most are correct as written — the top four files are the ones whose subject *is* crossing levels (a cross-level echo mechanism, a transitions file, a comparison file). A heading-as-register check would emit ~73 findings, mostly right, which is the noise level at which a guard gets switched off during the work it should protect.

**Plant-table shape.** One row per plant, one column per chapter carrying an instance; cells numbered `#1`, `#2`, … in chapter order and naming how the instance appears; `—` for no instance; the payoff instance marked as the payoff. A plant carries more than one instance before its payoff — a reader who meets an element once does not retrieve it twenty chapters later. → `init.md` for the scaffold, `coherence-check.md` J for the instance-count and gap checks.
